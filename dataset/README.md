# 车网互动充电功率预测数据集（15min 颗粒度，全量，v2）

> 由开源数据集 *A dataset of EV sheet* 全量转换而来（详见 `convert_full.py`）。
> 本版本（v2）按发改委 5 项整改意见重新组织：每 case 一个目标网格、≥30 个自然日历史、末日 7 天连续、真值口径"先按枪求窗口平均再求和"。

## 二、整改后的设计原则

按发改委 5 项整改意见：

1. **每 case 一个目标网格**：每个 `data/case_xxx.csv` 只包含一个目标网格（`station_id`）。
2. **预测发起时刻前 ≥ 7  个自然日连续**：每个 case 的 data 末日往前 7 天每天都有采样（7 天连续）。
3. **每 case 历史输入跨度 ≥ 30 个自然日**：data 跨度强制 = 30 天；超大场站 30 段每段~41 天（含余量）。
4. **每 case 末尾 4 天真值**（384 个 15min 步），按 `forecast_horizon = 2h/4h/1d/4d` 输出 504 行。
5. **同 station 不同 case 时间不交叉**：超大场站按日期均切 30 段互不重叠，小场站按 station_key 轮询分 4 组互不重叠。
6. **真值口径（整改3）**：`groupby(['w','pile_key']).mean().groupby('w').sum() / 1000` —— 先按充电枪求 15min 窗口平均，再对网格内全部充电枪求和并转换为 kW。
7. **date 与 report_time 一致**：`date` 严格取 `report_time` 的自然日期。
8. **完全重复行 = 0**：data 已做 (transaction_id, report_time) 跨表去重与按 (w, pile_key) 窗口聚合，无重复。
9. **status 与 power 逻辑一致**：仅生成 `status ∈ {0,1}`（按 power_w>0 判定），不存在 status=2 与 power>0 冲突。

| | `has_major_event` | 0 |
| **伪造(16)** | 7×行政区字段 + 6×网格设施字段 + `grid_id`/`temperature_c`/`rainfall_mm`/`grid_area_km2` | 确定性生成（文档化） |

## 五、已知限制

- **无放电**：源数据 `out_power` 全 ≥0，**当前数据集不含放电（V2G）**；若需充放电双向预测，需数据方补放电数据。
- **17 个伪造列**（行政区 NEV、网格设施等）：源数据无对应字段，按统一规则生成，模型不应作为关键信号依赖。
- **超大场站占全量 95%**（`440201004000`，15 个充电桩跨 8 个数据方）：切 30 段后仍主导数据分布。
