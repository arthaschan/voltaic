# /predict 接口服务 —— 手动操作与测试手册（下飞机照做即可）

> 编写日期：2026-08-24
> 适用：北京离线 H20 机房（也适用于阿里云测试 H20）
> 目标：把"车网互动充电功率预测"模型包装成评测平台要求的 HTTP 接口，CSV 输入 → CSV 输出。

---

## 一、这是什么（一句话）

评测平台（详见《大规模车网互动智能运营优化.docx》《交互规范.docx》）要求模型服务在容器内监听 **8000/tcp**，提供两个接口：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/health` | GET | 健康检查，返回 `{"status":"healthy", ...}` |
| `/predict` | POST | 推理：JSON `{"input":"<28字段CSV文本>","case_id":"001"}` → JSON `{"output":"<4字段CSV文本504行>","case_id","error_code","error_msg"}` |

- 输入 CSV：28 字段（date/operator_id/station_id/connector_id/connector_status/current_a/voltage_v/power_w/report_time/grid_id/…，至少要有 `report_time`、`connector_id`、`power_w` 三列）。
- 输出 CSV：4 字段 `forecast_horizon,step_index,forecast_timestamp,power_kw`，共 **504 行**（2h=8 步 + 4h=16 步 + 1d=96 步 + 4d=384 步）。
- 模型由环境变量 `MODEL` 决定（默认 `demmfl`），可选 7 个：`allzero / slotmedian / lightgbm / demmfl / gru / patchtst / timesnet`。

> **注意**：成功与错误响应都是 **HTTP 200**；错误信息在 body 的 `error_code`/`error_msg` 字段里（`error_code=null` 表示成功）。这是评测平台规范（《交互规范.docx》）的做法，不是 4xx/5xx。

## 四、手动操作步骤

### 4.1 方案一：离线包（北京离线机房推荐，不依赖 Docker）

```bash
# ① 把 excharge-offline.tar.gz 拷到 H20（U盘/硬盘），解压
mkdir -p ~/excharge && tar xzf excharge-offline.tar.gz -C ~/excharge
cd ~/excharge

# ② 一键离线安装（包内自带 Python 3.11 + 全部 wheel，全程不联网）
bash offline_install.sh
# 预期末尾输出：torch 2.13.0+cpu | lgb 4.7.0 | flask 3.1.x

# ③ 启动服务（前台，占用当前终端）
bash start_service.sh
# 预期输出：充电功率预测界面已启动: http://0.0.0.0:8000

# ④ 另开一个终端，跑测试
bash test_service.sh http://127.0.0.1:8000
# 预期：5 个用例全 ✓，结果 5 通过 0 失败
```

### 4.2 方案二：Docker 镜像（H20 已装 Docker 时更省事）

```bash
# ① 导入镜像（离线）
gunzip -c excharge-pred.tar.gz | docker load
docker images | grep excharge-pred   # 应看到 excharge-pred:latest

# ② 启动（默认模型 demmfl，端口 8000）
docker run -d --rm -p 8000:8000 --name excharge-service excharge-pred:latest

# ③ 等 5~8 秒后测试
curl http://127.0.0.1:8000/health
bash test_service.sh http://127.0.0.1:8000
```

### 4.3 换模型 / 7 模型对照

```bash
# 换模型：启动时设 MODEL（离线包）
MODEL=lightgbm bash start_service.sh

# 7 模型对照（一次性返回 7 个模型的 CSV，本机对比用）
ALL_MODELS=1 bash start_service.sh
# 此时 /predict 的 output 变成 {"lightgbm":"<CSV>", "demmfl":"<CSV>", ...}
```

### 4.4 手动 curl 单条测试（不用脚本）

```bash
# 健康检查
curl http://127.0.0.1:8000/health

# 推理（从数据集取前 96 行构造 input）
python3 -c "
import pandas as pd, json, urllib.request
df = pd.read_csv('dataset/data/case_001.csv').head(96)
csv_text = df.to_csv(index=False)
payload = json.dumps({'input': csv_text, 'case_id': '001'}).encode()
req = urllib.request.Request('http://127.0.0.1:8000/predict', data=payload, headers={'Content-Type':'application/json'})
r = json.loads(urllib.request.urlopen(req, timeout=180).read())
print('case_id:', r['case_id'], '| error:', r['error_code'])
print('output 前3行:'); print('\n'.join(r['output'].split(chr(10))[:4]))
"
```

## 六、常见问题（FAQ）

1. **启动报 `ModuleNotFoundError: flask`**：没跑 `offline_install.sh`，或 wheels 不完整。先 `bash offline_install.sh`。
2. **`/predict` 返回 `MODEL_NOT_READY`**：服务刚启动还在预热，等几秒再试。
3. **`/predict` 超时**：默认 demmfl 是逐 case 现场训练（LassoCV），输入数据大时可能几十秒；GRU/PatchTST/TimesNet 更慢。可设 `MODEL=slotmedian`（最快）或 `MODEL=lightgbm`（用预训练模型，秒级）。
4. **lightgbm 报 `libgomp.so.1` 缺失**：Docker 镜像内已预装；裸机离线包需 `apt-get install libgomp1`（离线包内含 `libgomp1_amd64.deb` 备用）。
5. **端口 8000 被占**：`PORT=8001 bash start_service.sh`，测试加参数 `bash test_service.sh http://127.0.0.1:8001`。
6. **想换 GPU 版 torch**：本项目 CPU-only 已够用，不建议换（会引入 CUDA/驱动兼容问题）。
7. **昇腾 910C（aarch64 NPU）**：本包是 x86_64 的；若上昇腾需另备 aarch64 wheel，且 `torch.cuda.is_available()` 会自动回退 CPU。
