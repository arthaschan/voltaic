# 镜像包如何分发到 Git 仓库（大文件策略）

> 问题：Docker 镜像 `excharge-pred.tar.gz` 约 500MB，离线包 `excharge-offline.tar.gz` 约 264MB，
> 直接 `git push` 到 GitHub 会被拒绝。本文说明正确的分发方式。

---

## 一、为什么不能直接 push 到 GitHub git 仓库

GitHub 对 git 仓库有硬限制：

| 限制 | 值 |
|------|-----|
| 单文件硬上限 | **100MB**（超过直接拒绝 push） |
| 单文件警告 | 50MB |
| 仓库建议上限 | 1GB |

500MB 的镜像包远超 100MB 单文件上限，`git push` 会报
`remote: error: File excharge-pred.tar.gz is 512.00 MB; this exceeds GitHub's file size limit of 100.00 MB`。

所以：**二进制大文件不进 git 正文**，走下面三条路。

---

## 二、方案 A：推送到容器镜像仓库（推荐）

Docker 镜像的正确归宿是**镜像仓库**（registry），不是 git。GitHub 自带 ghcr.io（GitHub Container Registry），`docker push` 原生支持分层上传，没有 100MB 单文件限制。

```bash
# 1) 登录 ghcr.io（需要 GitHub Personal Access Token，scope 勾选 write:packages）
echo "<你的PAT>" | docker login ghcr.io -u arthaschan --password-stdin

# 2) 打 tag 并推送
docker tag excharge-pred:latest ghcr.io/arthaschan/voltaic:latest
docker push ghcr.io/arthaschan/voltaic:latest
```

一键脚本见 `code/push_image_ghcr.sh`。

优点：分层、可增量、`docker pull` 直接可用，镜像体积不占 LFS 配额。
局限：目标机拉取需要能访问 ghcr.io（你"采购的 H20 服务"若有外网即可用；北京离线机房拉不了，仍需离线 tar）。

---

## 三、方案 B：Git LFS（次选）

git-lfs 把大文件存到 LFS 服务器，git 仓库里只存指针。可 push 到 GitHub，但：

- 需先装 git-lfs（`sudo apt-get install git-lfs && git lfs install`）。
- GitHub 免费 LFS 配额：**存储 1GB / 每月带宽 1GB**。镜像 500MB + 离线包 264MB 已接近上限，且每次 clone/拉取都消耗带宽。
- 北京离线 H20 根本拉不了 LFS，等于没意义。

```bash
git lfs track "*.tar.gz"
git add .gitattributes excharge-pred.tar.gz
git commit -m "chore: add docker image (lfs)"
git push
```

**仅在**"只想在 GitHub 上存个备份、且接受配额"时才用。

---

## 四、方案 C：物理介质（北京离线机房的唯一通道）

北京离线 H20 无法访问任何网络，无论 git 还是 registry 都拉不到。最终落地靠物理介质：

- U 盘 / 移动硬盘 / 加密盘，把 `excharge-pred.tar.gz`（或 `excharge-offline.tar.gz`）拷过去。
- 到 H20 后 `docker load` / 解压安装（见方案一/方案二文档）。

所以真正的离线交付物就是这两个 tar 包，git/registry 只是给"有外网的那台 H20 服务"做便捷分发。

---

## 五、建议组合

| 场景 | 用什么 |
|------|--------|
| 代码 + Dockerfile + 文档（小文件） | 正常 `git push`（已就绪） |
| 采购的 H20 服务（有外网） | 方案 A：`docker push` 到 ghcr.io，H20 上 `docker pull` |
| 北京离线 H20 机房 | 方案 C：物理介质拷贝 tar 包，`docker load` |
| 想在 GitHub 存镜像备份 | 方案 B：git-lfs（注意配额） |

> 提醒：`wheels/`（268MB）与 `*.tar.gz` 已在 `.gitignore` 里，不会被误提交。若你坚持要 push 大文件，务必用上面的 A/B 方案之一，不要直接 `git add` 大文件。
