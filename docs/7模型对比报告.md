## 三、关键发现（必须诚实面对）

### 1. 之前 rolling-origin 评估存在数据泄漏

之前的 `train_eval.py` 用 rolling-origin（每个 case 内部取 3 个滚动起点 + 最终 gt）评估，报告"TimesNet MAE 27.23 最优、超过 All-Zero"。但核查发现：`model_zoo.collect_windows` 用 `linspace(0, max_start)` 在整个序列上采样训练窗口，**训练时已经把序列末尾的 384 步（正是 rolling 内部起点的测试真值）用作训练样本**——存在数据泄漏。

改用真 out-of-sample（预测 gt 4 天，gt 在训练 data 之外）后，深度模型表现大幅回落：TimesNet MAE 从 27.23 → **37.08（不如 All-Zero）**，PatchTST 从 30.36 → 33.74。

### 2. 稀疏场景下，简单统计方法反而最稳

- **Slot-Median（同时段历史中位数）MAE 最低（27.68）**：因为它用"长期统计"而非"近期状态"，对"gt 恰好落在充电低谷"这类情况更稳健。
- 深度模型（PatchTST/TimesNet）依赖"近期 672 步"外推，在 gt 4 天恰好稀疏时，会预测假阳性，MAE 反而比"全零"更差。

### 3. 双方各有所长（互补）

| 维度 | 更优方 |
|------|--------|
| 点预测 MAE | 教授（Slot-Median / DEMMFL / GRU） |
| 非零步 MAPE | 教授（GRU 77% / DEMMFL 78% vs 我方 90%+） |
| 事件检测 F1 | 教授（DEMMFL 0.715 / GRU 0.713 vs 我方 0.70 以下） |
| 解决"两阶段塌缩" | 我方（活跃枪数让 F1 从 0 到 0.696；教授 Hurdle 在其数据上 F1=0） |
| 方法多样性 | 我方（已实现 PatchTST/TimesNet，教授建议"后续引入"） |

### 4. WAPE 异常大说明数据切分问题

WAPE = Σ|y−ŷ|/Σ|y|，理论值应接近 1。但本结果各模型 WAPE 达 15~29，说明**很多 case 的 gt 4 天几乎全零（真值总和极小），而模型预测了假阳性**。根因：`convert_full.py` 把超大场站按时间随机切 30 段，每段的"末尾 4 天"可能恰好落在充电低谷。这会高估假阳性的代价。

## 四、结论与建议

1. **不要盲目相信深度模型**：在稀疏充电场景，简单统计（Slot-Median）+ 特征工程（DEMMFL）比 Transformer 更稳。
2. **统一用"预测 gt 4 天"作为诚实口径**：废止 rolling-origin 内部起点的泄漏评估。
3. **最优组合建议**：Slot-Median 打底 + DEMMFL/GRU 增强 + 我方活跃枪数特征（解决塌缩、提升 F1）。
4. **数据层面**：gt 4 天应选择"有真实充电活动"的时段，避免随机窗口导致 gt 全零、评估失真。
